What You're Aiming For
Objective

The objective of this exercise is for high school students to get hands-on experience with key software development practices, including version control, continuous integration (CI), and quality assurance (QA). Through practical exercises, students will explore how these tools and methodologies can help streamline the development process, ensure code quality, and foster team collaboration.

Students will work on a small project, where they will learn to manage their code using Git, automate builds and tests using CI tools, and ensure their code meets quality standards with basic QA techniques.

Part 1: Version Control with Git

Implement the following steps to introduce students to version control using Git:

Initialize a Git repository for a project.
Stage, commit, and push changes to a remote repository (e.g., GitHub).
Collaborate with peers by pulling changes from a shared repository and resolving conflicts.
Create and manage branches to develop new features in isolation.
Use Git commands and GitHub’s interface to manage the codebase and collaborate with other students.

Example Behavior:

Students will stage and commit changes locally, then push to a shared repository. They will practice working on different branches and resolving merge conflicts when they arise.
Part 2: Continuous Integration (CI)

Introduce students to continuous integration by setting up an automated pipeline using a CI tool (e.g., GitHub Actions, Travis CI):

Create a simple pipeline that runs automated tests whenever changes are pushed to the repository.
Configure build steps to ensure the project compiles or runs correctly after each change.
Set up notifications to inform students if the build passes or fails.
Example Behavior:

Every time a student pushes code, the CI pipeline will run automated tests. If the tests pass, the build succeeds, otherwise, it fails, and the student is notified.
Part 3: Quality Assurance (QA)

Implement basic quality assurance techniques to ensure code quality:

Write unit tests for key features of the project.
Use a linter to check for code style consistency and common errors.
Review code from peers using pull requests and provide feedback.
Example Behavior:

Students will write tests for small sections of their code, run them through the CI pipeline, and correct any issues detected by the linter or peer feedback.

Instructions
Submit a GitHub link with:

Version Control: Submit the project repository, demonstrating the use of Git for version control, including branching and merging.
CI Pipeline: Submit the configuration for the CI pipeline that automatically runs tests and builds.
QA Report: Submit a brief report outlining the unit tests written, any code style issues detected by the linter, and a summary of code reviews conducted.
Short Reflection Report (200–300 words):

What challenges did you face while learning Git, CI, and QA tools?
How did the CI pipeline help streamline the development process?
How did version control and QA practices improve the collaboration and quality of your code?
