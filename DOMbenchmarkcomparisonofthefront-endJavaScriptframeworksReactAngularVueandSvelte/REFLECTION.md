# Reflection

**Challenges.** The hardest part was measuring fairly. Timing only "click to next frame" gave 18-20 ms for every framework, because the number was mostly time spent waiting for the next frame. I switched to timing from the click until the DOM was patched and laid out, and checked the row count at that point. Each framework also needed its own optimisation. In React I had to memoise rows and keep the callbacks stable. Angular needed OnPush, `track task.id` and immutable updates. In Svelte, whitespace between tags became extra text nodes, so I removed it.

**How each approach affected performance.** React's virtual DOM was fastest at rendering many rows: 26.0 ms for 1000 tasks, against 30.5 (Vue), 33.3 (Angular) and 36.7 ms (Svelte). It also used the least heap for 1000 tasks (3.2 MB, Angular 6.8 MB). Vue and Svelte create a reactive proxy for every task. That costs time at first render, but it pays off on updates. Changing 50 names took 1.7 ms in Vue and 1.8 ms in Svelte, against 1.9 ms in React and 2.1 ms in Angular. When I switched Svelte to `$state.raw`, rendering 1000 tasks dropped to 30.8 ms and Delete 50 from 2.7 to 1.3 ms. So the extra cost comes from the proxies, not from the compiled DOM code. Angular's runtime keeps extra comment anchors and view data, which made it the heaviest app in memory.

**Best performer.** React was the best at initial rendering (100, 500 and 1000 tasks). Vue and Svelte were best at small targeted updates. Angular, with immutable arrays and keyed tracking, was the fastest at deleting (1.6 ms). Svelte shipped the smallest bundle (16 KB gzip). The update and delete gaps are under one millisecond, while render differences reach 10 ms.
